（新建）## 修复：B 端"文件通道未就绪"竞态导致传输请求被静默丢弃

用户报告：A 向 B 发文件（有覆盖询问）失败，B 端日志 D:/relayFileGUI_2026-10-22.log 出现
`文件通道未就绪，丢弃帧, type=500`，A 重新传输后正常。

根因（FileSessionIO::ensureConnected 自等待死锁）：
- type=500 = kFileType_Request_Send。B 的文件通道 TCP 已连但 clientId 未登记 →
  ensureConnected 判未就绪 → 在 IO 线程 `QThread::msleep` 自旋 5s 等待 →
  但登记 ID 的 Answer_ID 帧必须由**同一个 IO 线程**的 handleFrame 处理，而它正被
  ensureConnected 阻塞——自己等自己，必然空等满 5s 后失败。
- 随后 handleFrame 返回，队列里的 Answer_ID 2ms 内处理完（日志：丢弃 .685、
  传输ID .685/.687），完美吻合。A 端只能等 RunTaskItem 30s 超时；B 端不弹覆盖询问框。

修复（未提交，待用户决定 tag 策略）：
1. ensureConnected 改为 QEventLoop + QTimer(10ms 轮询/5s 超时) 等待，允许嵌套
   （waitingDepth_ 成员防重复发起连接），等待期间队列帧可被处理，就绪即返回。
2. 新增 replyNotReady：未就绪丢弃时对 Request_Send/Request_Down 回失败应答
   （Answer_Send/Answer_Down，msgStateCode=Failed），对端立即失败而非 30s。
3. handleFrame 丢弃分支调用 replyNotReady。

验证：Release 0 warning、UnpackTest 14 项全过、200MB 环回 182MB/s sha256 一致。
